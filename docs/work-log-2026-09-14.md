# AegisFleet — 2026-09-14 engineering work log

## Completed in this session

- Hardened structured CALL-E result validation:
  - `task_completed` is now strictly boolean when present;
  - appointment evidence arrays reject malformed/non-string/blank entries instead of silently filtering them.
- Hardened appointment reconciliation:
  - first-visit instructions cannot be reported before positive patient identity;
  - first-visit instructions cannot be reported for a non-first visit;
  - first-visit confirmation requires all applicable administrative instructions.
- Hardened route reconciliation:
  - CALL-E `escalation_needed` is carried into the transaction evidence;
  - anything other than explicit `none` blocks route commit and enters recovery;
  - missing escalation status is therefore not treated as safe.
- Hardened transaction preparation in the orchestrator:
  - invalid prepared constraints are terminalized as `escalated` instead of leaving a `validated` record stranded;
  - transaction IDs include participant identity to avoid collisions across vehicles sharing an incident ID.
- Hardened audit ledger integrity:
  - public snapshots/history/reservations return deep copies;
  - stored audit events are detached from mutable caller-owned nested values;
  - legacy `complete()` follows `calling → verifying → resolved` when completion conditions are satisfied.
- Hardened the controlled live workflow:
  - unique `AEGIS_LIVE_TEST_ID=${{ github.run_id }}`;
  - explicit production CALL-E endpoint;
  - Polish `PL` / `pl-PL` defaults;
  - configuration validation;
  - authentication preflight;
  - regression tests and typecheck before the single live execution step.
- Corrected `.github/workflows/live-call.yml` so the controlled live test checks out the **current `main` branch**, not the historical `feat/voice-transaction-core-v5` branch.
